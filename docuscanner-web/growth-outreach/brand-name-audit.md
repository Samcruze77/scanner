### Confirmed customer-facing issues on the live site

1. **Privacy sentence, 26 pages:** "It is not uploaded to PDFScanner's servers. PDFScanner counts basic usage..." (shared constant `PRIVATE` in `utils/seo/landing.ts:58`, rendered under "Your files and privacy" on every landing, tool and converter page). 52 occurrences. This is the single biggest source.
2. **Protect pages (PDF, Word, Excel, PowerPoint):** "PDFScanner never sees the password...", "...is sent to PDFScanner", "Nobody, including PDFScanner..." (5 occurrences per page).
3. **Structured data on 18 tool/scanner/converter pages:** the schema.org `WebApplication` `name` is "PDFScanner PDF compressor", "PDFScanner OCR", etc. This is what search engines read as the app name.
4. **Guides:** 7 of the 8 guides carry body-copy occurrences (all except "How to convert images to PDF"; the alternatives guide alone has 8, the privacy guide 4). Three guides were written in this project's recent SEO release and repeat the same pattern.
5. **/guides meta description, og:description and twitter:description:** "...leading straight to the PDFScanner tool that does it."
6. **/account:** "Manage your PDFScanner account."
7. **FAQ answers on /scan, /scan-to-pdf, /pdf-to-text, /pdf-to-csv, /tools/ocr, /tools/sign-pdf, /tools/compress-pdf and others** ("Open PDFScanner in your phone's browser", "no PDFScanner watermark", "PDFScanner is supported by ads", ...).

### Not verifiable on the live site (marked unverified)

- `components/auth/ResetPasswordForm.tsx` (3 lines) and `components/tools/ProtectTool.tsx:325` render only after a user action (completing a password reset; protecting a file). The source is clear but I did not drive those states.
- Document properties written into downloaded files (`utils/convert/*`): Producer/Creator "PDFScanner" inside generated PDF/DOCX/XLSX files. These are not in page HTML.
- Authentication emails sent by Supabase/Brevo (subjects, sender display name, templates): configured outside this repository (Supabase dashboard / Brevo); I cannot inspect them. See section 7.
- `/admin` is sign-in gated; its text is known only from source.
- Third-party sites (directories, search results, social profiles): none were checked; no listings have been submitted.

## 2. Method and limits

- Source search: case-insensitive regex `pdf[ _-]?scanner` (covers PDFScanner, PDF Scanner, PdfScanner, pdfscanner, PDF-Scanner, PDF_Scanner), then separating matches preceded by "Free" (already correct). Related variants also searched: `DocuScanner`, `DocScanner`, `DocumentScanner`, spaced/hyphenated "Free PDF Scanner" (none found). Scope: all of `docuscanner-web/` excluding `node_modules/`, `.next/`, lockfiles; plus a separate pass over the repository root (legacy mobile app, backend, docs, generated `web-build/`).
- Binary assets (PNG/ICO, the two handover PDFs) cannot be text-searched. `public/brand/logo-full.png` was viewed and reads "FreePDFScanner.com". The `/og` image is generated by `app/og/route.tsx` from the same logo; not pixel-inspected.
- Live pass: HTTP fetch of rendered HTML for every page above, separated into `<title>`, meta tags, JSON-LD, accessible attributes (alt, aria-label, title, placeholder) and visible text (scripts and head removed). Client-only UI states (dialogs, errors, post-action messages) are not in server HTML and are marked unverified.
- Matching of source lines to live routes is by normalized text; "Appears live?" lists up to 5 routes per line.
